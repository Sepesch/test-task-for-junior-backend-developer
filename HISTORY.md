- Задачи должны создаваться с учетом этих настроек? По смыслу: периодическая задача — это шаблон, по которому генерируются экземпляры задач на нужные даты. Но в текущей системе задачи — это отдельные сущности. Как лучше? В задании сказано: "сделать так, чтобы задачи в трекере создавались с учетом этих настроек". Но нужно учесть, что даты могут быть в будущем и прошлом? Лучше: задача с периодичностью — это шаблон, и система периодически (по крон-джобе) создает задачи из шаблона. Но это усложнение.

- Добавить в БД новую таблицу recurring_tasks (id, task_template_id?, recurrence_type, recurrence_config). Либо расширить tasks полями recurrence_type, recurrence_config, is_recurring. При создании задачи, если передан recurrence, то создается запись в tasks с флагом is_recurring=true и соответствующими полями. А также отдельно генерируются конкретные задачи на основе правила на определенный период (например, на один месяц вперед). При этом сгенерированные задачи имеют поле parent_recurring_id, чтобы знать, откуда они появились. При удалении recurring задачи удаляются и все её children. При обновлении recurring правила — пересоздаем children. Это уже сложновато.

Для "не слишком запутано" я предложу другой подход: не генерировать множество задач, а хранить одну задачу с правилом повторения. При GET /tasks возвращать такие задачи, но на клиенте отображать их как повторяющиеся с возможностью отметить выполнение конкретного экземпляра. Для отметки выполнения конкретного дня нужно создавать отдельную запись о выполнении (таблица task_instances). Это выглядит более грамотно архитектурно, но выходит за рамки простого CRUD.

Но календарь задач обычно показывает задачи на день. Если у пользователя есть периодическая задача "обзвон пациентов каждый день", то ему нужно каждый день видеть эту задачу. Но в списке задач она должна быть каждый день. Для этого либо генерировать задачи, либо показывать шаблон и динамически вычислять.

Я выберу путь генерации задач при создании периодичности. Будет просто: при POST /tasks с телом, содержащим recurrence, система создает несколько задач (вставка в tasks) согласно правилу. При этом сама задача-шаблон не сохраняется. Пользователь сразу получает список созданных задач. Это просто и понятно. Например, если выбрано "ежедневные каждый 2-й день", начиная с сегодня на 10 дней вперед, создаются задачи на сегодня, послезавтра и т.д. Для ежемесячных — на ближайшие 12 месяцев. Для конкретных дат — на каждую дату. Для четных/нечетных — на все четные/нечетные числа текущего месяца и следующих нескольких месяцев.

Но мы должны учесть, что у задачи есть поля title, description, status. Все сгенерированные задачи будут одинаковы по содержанию, но с разными created_at? В текущей модели нет поля "date" для задачи. Задачи имеют только created_at и updated_at. Обычно в трекере у задачи есть дата выполнения или срок. В текущем проекте нет поля "due_date". Это проблема, потому что периодические задачи должны быть привязаны к конкретным датам выполнения. Скорее всего, в реальном приложении есть поле due_date, но здесь его нет. ## Моё понимание задачи и предлагаемое решение

Требуется добавить **настройки периодичности задачи**. При этом:
- Типы: ежедневные (каждый N-й день), ежемесячные (число месяца 1–30), конкретные даты, чётные/нечётные дни месяца.
- Нужно, чтобы задачи **создавались** согласно этим настройкам (а не просто хранили правило).
- Код должен быть рабочим, без излишней сложности.

### Архитектурное решение

Я предлагаю:
1. Добавить в таблицу `tasks` поле `due_date` (дата, на которую запланирована задача). Это естественно для трекера.
2. Оставить существующий `POST /api/v1/tasks` для создания **одной** задачи (без периодичности) – обратная совместимость.
3. Добавить **новый endpoint** `POST /api/v1/tasks/recurring`, который принимает правила периодичности и создаёт **множество задач** (по одной на каждую подходящую дату).  
   - У каждой созданной задачи будет свой `due_date`, одинаковые `title`, `description`, статус `new`.
   - Генерация ограничена разумным горизонтом (например, на 6 месяцев вперёд), чтобы не завалить БД.
4. При обновлении или удалении периодической задачи ничего дополнительного не делать – это обычные задачи, каждая живёт своей жизнью.  
   Если нужно изменить правило – удалить старый набор и создать новый.

Это просто, работает сразу, не требует фоновых процессов и не усложняет существующий CRUD.

```go
package recurrence

import (
    "fmt"
    "time"
)

type Type string

const (
    Daily       Type = "daily"
    Monthly     Type = "monthly"
    Specific    Type = "specific_dates"
    EvenOdd     Type = "even_odd"
)

type Rule struct {
    Type       Type     `json:"type"`
    Interval   int      `json:"interval,omitempty"`    // for daily
    DayOfMonth int      `json:"day_of_month,omitempty"`// for monthly (1-30)
    Dates      []string `json:"dates,omitempty"`       // for specific_dates (YYYY-MM-DD)
    Parity     string   `json:"parity,omitempty"`      // "even" or "odd" for even_odd
}

func GenerateDates(rule Rule, from time.Time, limitMonths int) ([]time.Time, error) {
    from = from.UTC().Truncate(24 * time.Hour)
    limit := from.AddDate(0, limitMonths, 0)

    switch rule.Type {
    case Daily:
        if rule.Interval < 1 {
            return nil, fmt.Errorf("interval must be >=1")
        }
        var dates []time.Time
        for d := from; !d.After(limit); d = d.AddDate(0, 0, rule.Interval) {
            dates = append(dates, d)
        }
        return dates, nil

    case Monthly:
        if rule.DayOfMonth < 1 || rule.DayOfMonth > 30 {
            return nil, fmt.Errorf("day_of_month must be 1-30")
        }
        var dates []time.Time
        y, m, _ := from.Date()
        current := time.Date(y, m, rule.DayOfMonth, 0, 0, 0, 0, time.UTC)
        if current.Before(from) {
            current = current.AddDate(0, 1, 0)
        }
        for !current.After(limit) {
            dates = append(dates, current)
            current = current.AddDate(0, 1, 0)
        }
        return dates, nil

    case Specific:
        var dates []time.Time
        for _, ds := range rule.Dates {
            d, err := time.Parse("2006-01-02", ds)
            if err != nil {
                return nil, fmt.Errorf("invalid date %s: %w", ds, err)
            }
            if d.Before(from) {
                continue
            }
            dates = append(dates, d)
        }
        return dates, nil

    case EvenOdd:
        if rule.Parity != "even" && rule.Parity != "odd" {
            return nil, fmt.Errorf("parity must be even or odd")
        }
        var dates []time.Time
        for d := from; !d.After(limit); d = d.AddDate(0, 0, 1) {
            day := d.Day()
            if rule.Parity == "even" && day%2 == 0 {
                dates = append(dates, d)
            } else if rule.Parity == "odd" && day%2 == 1 {
                dates = append(dates, d)
            }
        }
        return dates, nil

    default:
        return nil, fmt.Errorf("unknown recurrence type")
    }
}
```

### `internal/usecase/task/service.go` – добавить метод CreateRecurring

```go
func (s *Service) CreateRecurring(ctx context.Context, input CreateRecurringInput) ([]*taskdomain.Task, error) {
    if err := validateCreateInput(CreateInput{
        Title:       input.Title,
        Description: input.Description,
        Status:      input.Status,
    }); err != nil {
        return nil, err
    }

    // генерируем даты
    dates, err := recurrence.GenerateDates(input.Recurrence, s.now(), 6) // 6 months horizon
    if err != nil {
        return nil, fmt.Errorf("%w: %v", ErrInvalidInput, err)
    }
    if len(dates) == 0 {
        return nil, fmt.Errorf("%w: no dates generated", ErrInvalidInput)
    }
    if len(dates) > 100 {
        return nil, fmt.Errorf("%w: too many tasks (%d), limit 100", ErrInvalidInput, len(dates))
    }

    var tasks []*taskdomain.Task
    for _, due := range dates {
        task := &taskdomain.Task{
            Title:       input.Title,
            Description: input.Description,
            Status:      input.Status,
            DueDate:     &due,
            CreatedAt:   s.now(),
            UpdatedAt:   s.now(),
        }
        created, err := s.repo.Create(ctx, task)
        if err != nil {
            return nil, err
        }
        tasks = append(tasks, created)
    }
    return tasks, nil
}

## 3. Генератор периодичности

**`internal/recurrence/generator.go`**

```go
package recurrence

import (
	"fmt"
	"time"
)

type Type string

const (
	Daily     Type = "daily"
	Monthly   Type = "monthly"
	Specific  Type = "specific_dates"
	EvenOdd   Type = "even_odd"
)

type Rule struct {
	Type       Type     `json:"type"`
	Interval   int      `json:"interval,omitempty"`        // for daily (each N-th day)
	DayOfMonth int      `json:"day_of_month,omitempty"`    // for monthly (1-30)
	Dates      []string `json:"dates,omitempty"`           // for specific_dates (YYYY-MM-DD)
	Parity     string   `json:"parity,omitempty"`          // "even" or "odd"
}

// GenerateDates returns list of UTC dates (truncated to day) from today up to limitMonths ahead.
func GenerateDates(rule Rule, from time.Time, limitMonths int) ([]time.Time, error) {
	from = from.UTC().Truncate(24 * time.Hour)
	limit := from.AddDate(0, limitMonths, 0)

	switch rule.Type {
	case Daily:
		if rule.Interval < 1 {
			return nil, fmt.Errorf("interval must be >= 1")
		}
		var dates []time.Time
		for d := from; !d.After(limit); d = d.AddDate(0, 0, rule.Interval) {
			dates = append(dates, d)
		}
		return dates, nil

	case Monthly:
		if rule.DayOfMonth < 1 || rule.DayOfMonth > 30 {
			return nil, fmt.Errorf("day_of_month must be between 1 and 30")
		}
		var dates []time.Time
		y, m, _ := from.Date()
		first := time.Date(y, m, rule.DayOfMonth, 0, 0, 0, 0, time.UTC)
		if first.Before(from) {
			first = first.AddDate(0, 1, 0)
		}
		for d := first; !d.After(limit); d = d.AddDate(0, 1, 0) {
			dates = append(dates, d)
		}
		return dates, nil

	case Specific:
		var dates []time.Time
		for _, ds := range rule.Dates {
			d, err := time.Parse("2006-01-02", ds)
			if err != nil {
				return nil, fmt.Errorf("invalid date %s: %w", ds, err)
			}
			date := d.UTC()
			if date.Before(from) {
				continue
			}
			dates = append(dates, date)
		}
		return dates, nil

	case EvenOdd:
		if rule.Parity != "even" && rule.Parity != "odd" {
			return nil, fmt.Errorf("parity must be 'even' or 'odd'")
		}
		var dates []time.Time
		for d := from; !d.After(limit); d = d.AddDate(0, 0, 1) {
			day := d.Day()
			if rule.Parity == "even" && day%2 == 0 {
				dates = append(dates, d)
			} else if rule.Parity == "odd" && day%2 == 1 {
				dates = append(dates, d)
			}
		}
		return dates, nil

	default:
		return nil, fmt.Errorf("unknown recurrence type: %s", rule.Type)
	}
}
```

func (s *Service) CreateRecurring(ctx context.Context, input CreateRecurringInput) ([]*taskdomain.Task, error) {
	// валидируем базовые поля (как при обычном создании)
	if _, err := validateCreateInput(CreateInput{
		Title:       input.Title,
		Description: input.Description,
		Status:      input.Status,
	}); err != nil {
		return nil, err
	}

	// генерируем даты на 6 месяцев вперёд
	dates, err := recurrence.GenerateDates(input.Recurrence, s.now(), 6)
	if err != nil {
		return nil, fmt.Errorf("%w: %v", ErrInvalidInput, err)
	}

	if len(dates) == 0 {
		return nil, fmt.Errorf("%w: no dates generated for given recurrence", ErrInvalidInput)
	}
	if len(dates) > 100 {
		return nil, fmt.Errorf("%w: too many tasks (%d), limit 100", ErrInvalidInput, len(dates))
	}

	var tasks []*taskdomain.Task
	now := s.now()

	for _, scheduledAt := range dates {
		task := &taskdomain.Task{
			Title:       input.Title,
			Description: input.Description,
			Status:      input.Status,
			ScheduledAt: &scheduledAt,
			CreatedAt:   now,
			UpdatedAt:   now,
		}
		created, err := s.repo.Create(ctx, task)
		if err != nil {
			return nil, err
		}
		tasks = append(tasks, created)
	}
	return tasks, nil
}

## Идея решения

При создании периодической задачи мы **сразу генерируем и сохраняем в БД много обычных задач** – по одной на каждую дату, когда задача должна быть выполнена. У каждой такой задачи есть поле `scheduled_at` (дата выполнения). Пользователь получает список созданных задач и может работать с каждой из них независимо (выполнить, отложить, удалить).

## Архитектура

1. **В таблицу `tasks` добавляется колонка `scheduled_at DATE`** (или `TIMESTAMPTZ`). Она хранит дату, на которую запланирована задача.
2. **Новый endpoint** `POST /api/v1/tasks/recurring` принимает правило повторения (тип и параметры).
3. **Генератор дат** (пакет `recurrence`) вычисляет все даты в заданном интервале (например, на 6 месяцев вперёд) по правилу.
4. **Сервис (`taskUsecase`)** для каждой даты вызывает обычный `repo.Create` с заполненным `ScheduledAt`.
5. **Ответ – массив созданных задач**, каждая со своим ID и `scheduled_at`.

## Пример работы

### Запрос:

```json
POST /api/v1/tasks/recurring
{
  "title": "Обзвон пациентов",
  "description": "Каждые 2 дня",
  "recurrence": {
    "type": "daily",
    "interval": 2
  }
}
```

### Система вычисляет даты:

Сегодня `2026-05-05`. Генератор выдаёт:  
`2026-05-05`, `2026-05-07`, `2026-05-09`, … до `2026-11-05` (6 месяцев).

### Создаются записи в `tasks`:

| id | title            | scheduled_at | status |
|----|------------------|--------------|--------|
| 1  | Обзвон пациентов | 2026-05-05   | new    |
| 2  | Обзвон пациентов | 2026-05-07   | new    |
| 3  | Обзвон пациентов | 2026-05-09   | new    |
| ... | ...              | ...          | new    |

### Пользователь видит все задачи в списке, может выполнить задачу на 5 мая, остальные остаются.

## Где здесь минусы?

- **Много дублирования** – одна и та же информация (заголовок, описание) повторяется в каждой задаче.
- **Если правило нужно изменить** – старые задачи не обновятся автоматически. Придётся удалить старый набор и создать новый.
- **Может быть слишком много задач** (если интервал маленький, а горизонт большой) – возможна перегрузка БД/памяти.

Потому что задание было **«сделать так, чтобы задачи в трекере создавались»** (буквально) и **«не слишком запутано»**. // EvenOddRecurrence представляет правило "чётные/нечётные дни месяца"
type EvenOddRecurrence struct {
	Parity string `json:"parity"` // "even" или "odd"
}

func (r EvenOddRecurrence) RecurrenceType() string { return "even_odd" }

func (r EvenOddRecurrence) Valid() error {
	if r.Parity != "even" && r.Parity != "odd" {
		return fmt.Errorf("parity must be 'even' or 'odd'")
	}
	return nil
}

func (r EvenOddRecurrence) NextOccurrence(from time.Time) *time.Time {
	from = truncateToDate(from)
	// Начинаем поиск со следующего дня, потому что сам from уже мог быть сегодня
	candidate := from.AddDate(0, 0, 1)
	// Защита от бесконечного цикла – ищем максимум 31 день вперёд
	for i := 0; i < 31; i++ {
		day := candidate.Day()
		if r.Parity == "even" && day%2 == 0 {
			return &candidate
		}
		if r.Parity == "odd" && day%2 == 1 {
			return &candidate
		}
		candidate = candidate.AddDate(0, 0, 1)
	}
	// Не нашли (не бывает, но на всякий случай)
	return nil
}
```

package task

import (
	"fmt"
	"time"
)

// Recurrence - интерфейс всех правил периодичности
type Recurrence interface {
	Type() string
	Validate() error
	NextOccurrence(after time.Time) (time.Time, bool)
}

// DailyRecurrence – каждые N дней
type DailyRecurrence struct {
	Interval int `json:"interval"`
}

func (r DailyRecurrence) Type() string { return "daily" }
func (r DailyRecurrence) Validate() error {
	if r.Interval <= 0 {
		return fmt.Errorf("interval must be positive")
	}
	return nil
}
func (r DailyRecurrence) NextOccurrence(after time.Time) (time.Time, bool) {
	next := after.AddDate(0, 0, r.Interval)
	return beginningOfDay(next), true
}

// MonthlyRecurrence – каждый месяц в указанный день (1-30)
type MonthlyRecurrence struct {
	DayOfMonth int `json:"day_of_month"`
}

func (r MonthlyRecurrence) Type() string { return "monthly" }
func (r MonthlyRecurrence) Validate() error {
	if r.DayOfMonth < 1 || r.DayOfMonth > 30 {
		return fmt.Errorf("day_of_month must be between 1 and 30")
	}
	return nil
}
func (r MonthlyRecurrence) NextOccurrence(after time.Time) (time.Time, bool) {
	// Пробуем в этом же месяце
	candidate := time.Date(after.Year(), after.Month(), r.DayOfMonth, 0, 0, 0, 0, time.UTC)
	if candidate.Before(after) || candidate.Equal(after) {
		candidate = candidate.AddDate(0, 1, 0)
	}
	// Коррекция: если указанного дня нет в месяце (например 30 февраля) – берём последний день месяца
	for candidate.Day() != r.DayOfMonth {
		candidate = candidate.AddDate(0, 1, 0)
	}
	return beginningOfDay(candidate), true
}

// WeeklyRecurrence – по указанным дням недели (1=пн ... 7=вс)
type WeeklyRecurrence struct {
	WeekDays []int `json:"week_days"`
}

func (r WeeklyRecurrence) Type() string { return "weekly" }
func (r WeeklyRecurrence) Validate() error {
	if len(r.WeekDays) == 0 {
		return fmt.Errorf("week_days cannot be empty")
	}
	seen := make(map[int]bool)
	for _, d := range r.WeekDays {
		if d < 1 || d > 7 {
			return fmt.Errorf("week day must be between 1 (mon) and 7 (sun)")
		}
		if seen[d] {
			return fmt.Errorf("duplicate week day: %d", d)
		}
		seen[d] = true
	}
	return nil
}
func (r WeeklyRecurrence) NextOccurrence(after time.Time) (time.Time, bool) {
	// Ищем следующий день после 'after'
	for d := 1; d <= 7; d++ {
		candidate := after.AddDate(0, 0, d)
		wd := isoWeekday(candidate)
		for _, target := range r.WeekDays {
			if wd == target {
				return beginningOfDay(candidate), true
			}
		}
	}
	return time.Time{}, false
}

// SpecificDatesRecurrence – только в указанные даты
type SpecificDatesRecurrence struct {
	Dates []string `json:"dates"` // YYYY-MM-DD
}

func (r SpecificDatesRecurrence) Type() string { return "specific_dates" }
func (r SpecificDatesRecurrence) Validate() error {
	if len(r.Dates) == 0 {
		return fmt.Errorf("dates cannot be empty")
	}
	for _, d := range r.Dates {
		if _, err := time.Parse("2006-01-02", d); err != nil {
			return fmt.Errorf("invalid date %q: %w", d, err)
		}
	}
	return nil
}
func (r SpecificDatesRecurrence) NextOccurrence(after time.Time) (time.Time, bool) {
	var earliest *time.Time
	for _, d := range r.Dates {
		t, _ := time.Parse("2006-01-02", d)
		t = beginningOfDay(t)
		if t.After(after) {
			if earliest == nil || t.Before(*earliest) {
				earliest = &t
			}
		}
	}
	if earliest == nil {
		return time.Time{}, false
	}
	return *earliest, true
}

// EvenOddRecurrence – чётные/нечётные дни месяца
type EvenOddRecurrence struct {
	Parity string `json:"parity"` // "even" или "odd"
}

func (r EvenOddRecurrence) Type() string { return "even_odd" }
func (r EvenOddRecurrence) Validate() error {
	if r.Parity != "even" && r.Parity != "odd" {
		return fmt.Errorf("parity must be 'even' or 'odd'")
	}
	return nil
}
func (r EvenOddRecurrence) NextOccurrence(after time.Time) (time.Time, bool) {
	// Начинаем поиск со следующего дня
	cur := beginningOfDay(after).AddDate(0, 0, 1)
	// Проверяем не более 31 дня вперёд
	for i := 0; i < 31; i++ {
		day := cur.Day()
		if r.Parity == "even" && day%2 == 0 {
			return cur, true
		}
		if r.Parity == "odd" && day%2 == 1 {
			return cur, true
		}
		cur = cur.AddDate(0, 0, 1)
	}
	return time.Time{}, false
}

// Вспомогательные функции
func beginningOfDay(t time.Time) time.Time {
	return time.Date(t.Year(), t.Month(), t.Day(), 0, 0, 0, 0, time.UTC)
}

func isoWeekday(t time.Time) int {
	wd := t.Weekday()
	if wd == 0 {
		return 7
	}
	return int(wd)
}

package task

import (
	"context"
	"log/slog"
	"time"

	taskdomain "example.com/taskservice/internal/domain/task"
)

type Scheduler struct {
	repo Repository
	now  func() time.Time
}

func NewScheduler(repo Repository) *Scheduler {
	return &Scheduler{
		repo: repo,
		now:  func() time.Time { return time.Now().UTC() },
	}
}

// Run запускает бесконечный цикл, который каждую полночь вызывает Tick
func (s *Scheduler) Run(ctx context.Context) {
	for {
		delay := s.durationUntilMidnight()
		select {
		case <-ctx.Done():
			return
		case <-time.After(delay):
		}
		if err := s.Tick(ctx); err != nil {
			slog.Error("scheduler tick failed", "error", err)
		}
	}
}

// Tick обрабатывает все просроченные задачи со статусом done
func (s *Scheduler) Tick(ctx context.Context) error {
	today := s.now()
	tasks, err := s.repo.ListDueRecurrences(ctx, today)
	if err != nil {
		return err
	}
	for _, t := range tasks {
		if err := s.resetTask(ctx, t, today); err != nil {
			slog.Error("reset recurring task", "task_id", t.ID, "error", err)
		}
	}
	return nil
}

func (s *Scheduler) resetTask(ctx context.Context, t taskdomain.Task, today time.Time) error {
	rec, _, err := s.repo.GetRecurrence(ctx, *t.RecurrenceID)
	if err != nil {
		return err
	}

	// Вычисляем следующую дату после today
	next, ok := rec.NextOccurrence(today)
	if ok {
		if err := s.repo.UpdateNextOccurrence(ctx, *t.RecurrenceID, next); err != nil {
			return err
		}
	}

	// Сбрасываем статус задачи в new
	t.Status = taskdomain.StatusNew
	t.UpdatedAt = today
	_, err = s.repo.Update(ctx, &t)
	return err
}

func (s *Scheduler) durationUntilMidnight() time.Duration {
	now := s.now()
	next := time.Date(now.Year(), now.Month(), now.Day()+1, 0, 0, 0, 0, now.Location())
	return next.Sub(now)
}

	case taskdomain.SpecificDatesRecurrence:
		resp.Dates = r.Dates
	case taskdomain.EvenOddRecurrence:

	}
	return resp

func mapRequestToRecurrence(req recurrenceRequest) (taskdomain.Recurrence, error) {
	switch req.Type {
	case "daily":
		if req.Interval == nil {
			return nil, &validationError{"missing interval for daily"}
		}
		return taskdomain.DailyRecurrence{Interval: *req.Interval}, nil
	case "monthly":
		if req.DayOfMonth == nil {
			return nil, &validationError{"missing day_of_month for monthly"}
		}
		return taskdomain.MonthlyRecurrence{DayOfMonth: *req.DayOfMonth}, nil
	case "weekly":
		if len(req.WeekDays) == 0 {
			return nil, &validationError{"missing week_days for weekly"}
		}
		return taskdomain.WeeklyRecurrence{WeekDays: req.WeekDays}, nil
	case "specific_dates":
		if len(req.Dates) == 0 {
			return nil, &validationError{"missing dates for specific_dates"}
		}
		return taskdomain.SpecificDatesRecurrence{Dates: req.Dates}, nil
	case "even_odd":
		if req.Parity == nil {
			return nil, &validationError{"missing parity for even_odd"}
		}
		return taskdomain.EvenOddRecurrence{Parity: *req.Parity}, nil
	default:
		return nil, &validationError{"unknown recurrence type: " + req.Type}
	}
}

# Task Service

## Recurring Tasks

You can attach recurrence rules to existing tasks. When a recurring task is marked as `done`, the scheduler will automatically reset it to `new` on the next occurrence date.

### API Endpoints for Recurrence

- `GET /api/v1/tasks/{id}/recurrence` – get recurrence settings
- `PUT /api/v1/tasks/{id}/recurrence` – set or replace recurrence
- `DELETE /api/v1/tasks/{id}/recurrence` – remove recurrence

### Supported recurrence types

| type          | fields                        | description                        |
|---------------|-------------------------------|------------------------------------|
| daily         | `interval` (int >0)           | every N days                       |
| monthly       | `day_of_month` (1-30)         | each month on the given day        |
| weekly        | `week_days` (1..7, 1=Monday)  | on selected weekdays               |
| specific_dates| `dates` (array of YYYY-MM-DD) | only on exact dates                |
| even_odd      | `parity` ("even"/"odd")       | on even or odd days of the month   |

### Example requests

```bash
# Set daily recurrence every 2 days
curl -X PUT /api/v1/tasks/1/recurrence -H "Content-Type: application/json" \
  -d '{"type":"daily","interval":2}'

# Set monthly on 15th
curl -X PUT /api/v1/tasks/1/recurrence -d '{"type":"monthly","day_of_month":15}'

# Set weekly on Mon/Wed/Fri
curl -X PUT /api/v1/tasks/1/recurrence -d '{"type":"weekly","week_days":[1,3,5]}'

# Set specific dates
curl -X PUT /api/v1/tasks/1/recurrence -d '{"type":"specific_dates","dates":["2026-06-01","2026-07-01"]}'

# Set even days
curl -X PUT /api/v1/tasks/1/recurrence -d '{"type":"even_odd","parity":"even"}'
```

### Assumptions

- The scheduler runs once a day at midnight (UTC) and resets tasks whose `next_occurrence_at` has passed.
- Recurrence is attached to a task, not to a template. If you delete the recurrence, the task becomes non-recurring.
- If you change the recurrence rule, the old one is deleted and a new one is created.

## Зачем это нужно?

- **Связать задачу с правилом периодичности** – `recurrence_id` (внешний ключ на `task_recurrences.id`) показывает, принадлежит ли задача к какому-то повторяющемуся правилу. Если `NULL` – задача обычная (один раз). Если число – значит, у задачи есть правило: когда она переходит в статус `done`, планировщик сбросит её обратно в `new` в следующую дату, указанную в `task_recurrences.next_occurrence_at`.

}

}

func (r *Repository) Create(ctx context.Context, task *taskdomain.Task) (*taskdomain.Task, error) {
	const query = `
		INSERT INTO tasks (title, description, status, created_at, updated_at, recurrence_id)
		VALUES ($1, $2, $3, $4, $5, $6)
		RETURNING id, title, description, status, created_at, updated_at, recurrence_id
	`

func (r *Repository) GetByID(ctx context.Context, id int64) (*taskdomain.Task, error) {
	const query = `
		SELECT id, title, description, status, created_at, updated_at, recurrence_id
		FROM tasks
		WHERE id = $1
	`

	task, err := scanTask(row)
	if errors.Is(err, pgx.ErrNoRows) {
		return nil, taskdomain.ErrNotFound
	}
	return task, err
}

		UPDATE tasks
		SET title = $1, description = $2, status = $3, updated_at = $4, recurrence_id = $5
		WHERE id = $6
		RETURNING id, title, description, status, created_at, updated_at, recurrence_id
	`

	updated, err := scanTask(row)
	if errors.Is(err, pgx.ErrNoRows) {
		return nil, taskdomain.ErrNotFound
	}
	return updated, err
}

func (r *Repository) Delete(ctx context.Context, id int64) error {
	const query = `DELETE FROM tasks WHERE id = $1`
	res, err := r.pool.Exec(ctx, query, id)
	if err != nil {
		return err
	}
	if res.RowsAffected() == 0 {
		return taskdomain.ErrNotFound
	}
	return nil
}

	const query = `
		SELECT id, title, description, status, created_at, updated_at, recurrence_id
		FROM tasks
		ORDER BY id DESC
	`

		return nil, err

	var tasks []taskdomain.Task
	for rows.Next() {
		t, err := scanTask(rows)
		if err != nil {
			return nil, err
		}
		tasks = append(tasks, *t)
	}
	return tasks, rows.Err()
}

	Scan(dest ...any) error
}) (*taskdomain.Task, error) {

		&task.Description,
		&status,
		&task.CreatedAt,
		&task.UpdatedAt,
		&task.RecurrenceID,
	)
	if err != nil {
		return nil, err
	}
	task.Status = taskdomain.Status(status)
	return &task, nil

## Что такое `recurrence_id`?

`recurrence_id` — это **внешний ключ** (foreign key) в таблице `tasks`, который ссылается на таблицу `task_recurrences`. Если у задачи есть такой `recurrence_id` ≠ `NULL`, значит она **является периодической** и подчиняется правилу, хранящемуся в таблице `task_recurrences`.

Правило периодичности описывает, как часто задача должна «возвращаться» в статус `new` после того, как её отметили `done`:
- `daily` (каждые N дней)
- `monthly` (определённое число месяца)
- `weekly` (дни недели)
- `specific_dates` (конкретные даты)
- `even_odd` (чётные/нечётные дни месяца)

Планировщик (`scheduler.go`) раз в сутки находит все задачи со статусом `done`, у которых `recurrence_id` не `NULL` и дата `next_occurrence_at` из `task_recurrences` уже наступила. Он сбрасывает их статус обратно в `new` и вычисляет следующую дату.

## Что делать, если задача одноразовая?

**Ничего специального не нужно.** Для одноразовой задачи:
- При создании не указывайте `recurrence_id` (оставьте `NULL`).
- Не вызывайте `PUT /api/v1/tasks/{id}/recurrence`.
- Поле `recurrence_id` в ответе `GET /tasks` будет либо отсутствовать (`omitempty`), либо равно `null`.

Такая задача ведёт себя как в оригинальном коде: после перевода в `done` она остаётся `done` навсегда. Планировщик её не трогает, потому что в выборку `ListDueRecurrences` попадают только задачи с `recurrence_id IS NOT NULL`.

## Итог

- `recurrence_id` = `NULL` → **одноразовая задача**, никакой периодичности.
- `recurrence_id` = число → **периодическая задача**, управляется планировщиком.
- Для обычных задач ничего менять не нужно — код полностью обратно совместим.

## DeepSeek

### Thinking
````
Мы видим, что в текущем `openapi.json` (из присланного пользователем) действительно нет `components/parameters`. Там есть `components/responses` и `components/schemas`, но `parameters` отсутствует. Нужно добавить этот раздел. Пользователь спрашивает, куда именно добавлять, так как у components нет поля parameters. Ответ: его нужно создать, как sibling для `responses` и `schemas` внутри `components`.
````

Вы правы, в текущем `openapi.json` действительно нет раздела `components/parameters`. Его нужно **создать**.

## Куда добавить

Внутри `"components"` у вас есть `"responses"` и `"schemas"`. Добавьте `"parameters"` как третий раздел, например после `"responses"`:

```json
"components": {
  "responses": { ... },
  "parameters": {
    "TaskID": {
      "name": "id",
      "in": "path",
      "required": true,
      "schema": {
        "type": "integer",
        "format": "int64",
        "minimum": 1
      }
    }
  },
  "schemas": { ... }
}
```

## Если не хотите добавлять отдельный параметр

Можно обойтись без `TaskID`, указав параметры прямо в `paths` для каждого эндпоинта, но это увеличит дублирование. Например, для `GET /tasks/{id}/recurrence`:

```json
"parameters": [
  {
    "name": "id",
    "in": "path",
    "required": true,
    "schema": { "type": "integer", "format": "int64", "minimum": 1 }
  }
]
```

Но **рекомендуется** создать `parameters/TaskID` – это красивее и соответствует принципу DRY.

## Итог

Просто добавьте блок `"parameters"` рядом с `"responses"` и `"schemas"`. Порядок не важен, но обычно `parameters` идёт перед `schemas`. Главное – чтобы JSON был валидным.
